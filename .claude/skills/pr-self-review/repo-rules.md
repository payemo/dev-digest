# Repo rules — the checks no vendored skill makes

Deterministic, repo-specific, and mostly one grep each. They run in phase 0,
before any lane, and they produce the most reliable CRITICALs in the run: no
model judgement is involved, only a path or a pattern.

Every command below assumes:

```sh
BASE=$(.claude/hooks/pr-self-review-gate.sh --print-base)
CHANGED=$(git diff --name-only "$BASE"; git ls-files --others --exclude-standard)
```

| ID | Severity | In one line |
|---|---|---|
| `RULE-MIGRATION` | CRITICAL | A migration file was hand-edited or renamed |
| `RULE-MIGRATION-MISSING` | WARNING | Schema changed, no migration generated |
| `RULE-LOCKFILE` | CRITICAL | A lockfile was hand-edited |
| `RULE-WRONG-PM` | CRITICAL | A package's lockfile is from the wrong package manager |
| `RULE-WORKSPACE` | CRITICAL | The four-package split is being turned into a workspace |
| `RULE-SECRET` | CRITICAL | A credential is in the diff or about to be staged |
| `RULE-CONTRACT-SYNC` | CRITICAL | The two `vendor/shared` copies diverged |
| `RULE-CONTRACT-BREAK` | WARNING | A contract changed without its consumers |
| `RULE-ALIAS-CI` | CRITICAL | A tsconfig alias changed, CI path filters did not |
| `RULE-INSIGHTS-LAST` | WARNING | `!**/INSIGHTS.md` is not last in a `paths:` list |
| `RULE-IT-SUFFIX` | CRITICAL | A DB-backed test is in the hermetic lane |
| `RULE-CORE-PURITY` | CRITICAL | `reviewer-core` grew a runtime dependency |
| `RULE-CLONES` | CRITICAL | `server/clones/**` is being committed |
| `RULE-VENDOR` | WARNING | Vendored code was edited in place |
| `RULE-PROMPT` | WARNING | A reviewer prompt broke its own conventions |
| `RULE-SKIPWORKTREE` | WARNING | `server/package.json` is in the diff |
| `RULE-LESSON` | WARNING | A course-lesson feature is landing on `main` |

---

### `RULE-MIGRATION` — CRITICAL

`server/src/db/migrations/**` is generated by `pnpm db:generate`; a hand edit
desyncs the journal hash. A modified (`M`) or renamed (`R`) `.sql` file or
`meta/*_snapshot.json` is always a finding.

```sh
git diff --name-status "$BASE" -- server/src/db/migrations \
  | grep -E '^(M|R)' | grep -vE 'meta/_journal\.json$'
```

**`meta/_journal.json` is the one legitimate `M`** — `db:generate` appends to it
every time it emits a migration. It is a finding only when it changed *without*
a new `NNNN_*.sql` + matching `meta/NNNN_snapshot.json` added in the same diff;
that combination means the journal was touched by hand.

Fix: revert the file, change `server/src/db/schema/*`, re-run `pnpm db:generate`.

### `RULE-MIGRATION-MISSING` — WARNING

`server/src/db/schema/**` changed but no new file under `migrations/` and no
`meta/_journal.json` update. Migrations never run on boot, so this ships a
schema the DB doesn't have.

### `RULE-LOCKFILE` — CRITICAL

A lockfile changed with no dependency change behind it, or its diff doesn't
look generated (a version bumped without the matching integrity/resolution
lines). Change deps through the package's own package manager instead.

```sh
git diff --name-only "$BASE" | grep -E '(pnpm-lock\.yaml|package-lock\.json)$'
```

`server/pnpm-lock.yaml` is the one soft case: `server/package.json` is
`skip-worktree`, so a legitimate dependency change there can appear
lockfile-only. Confirm with `git diff "$BASE" -- server/pnpm-lock.yaml` that
the change is generator-shaped before clearing it; report `RULE-SKIPWORKTREE`
alongside.

### `RULE-WRONG-PM` — CRITICAL

`server/` and `client/` are pnpm; `reviewer-core/` and `e2e/` are npm. A
lockfile of the wrong kind means the wrong install ran, and CI will not
reproduce it.

```sh
ls server/package-lock.json client/package-lock.json \
   reviewer-core/pnpm-lock.yaml e2e/pnpm-lock.yaml 2>/dev/null
```

### `RULE-WORKSPACE` — CRITICAL

A root `package.json`, `pnpm-workspace.yaml`, `turbo.json`, or a `workspaces`
field. The four standalone packages are deliberate and CI's path filters depend
on the split.

### `RULE-SECRET` — CRITICAL

Grep the **added** lines for credential shapes, and check the worktree for the
untracked `openrouter-api-key` file that sits at the repo root and is *not* in
`.gitignore`.

```sh
git diff "$BASE" -U0 | grep -E '^\+' | \
  grep -E 'sk-or-v1-|sk-ant-|ghp_|github_pat_|AKIA[0-9A-Z]{16}|xox[baprs]-|-----BEGIN [A-Z ]*PRIVATE KEY'
git status --porcelain -uall | grep -E '\?\? (openrouter-api-key|.*\.pem|.*\.key)$'
```

Secrets belong in `~/.devdigest/secrets.json` (mode `0600`) behind
`SecretsProvider`, never in `AppConfig`, the DB, or git. An untracked secret at
root is reported even though it is not in the diff — it is one `git add -A`
away from being in it.

**Test fixtures are the expected false positive.** `server/test/adapters.test.ts`
carries a literal `ghp_supersecrettoken` precisely to assert that redaction
works. A hit inside `**/test/**`, `**/*.test.ts`, `**/mocks.ts` or `*.example*`
is CRITICAL only if the value could be a live credential — an obviously fake
one is not a finding, and must not be "fixed" by deleting the assertion.

### `RULE-CONTRACT-SYNC` — CRITICAL

`client/src/vendor/shared` is a physical copy of `server/src/vendor/shared`,
and `client.yml` fails the build on drift before it installs anything.

```sh
diff -r client/src/vendor/shared server/src/vendor/shared
```

Fix: copy server's version over client's, both directories, contract for
contract, and commit that.

### `RULE-CONTRACT-BREAK` — WARNING

A field removed, renamed, or made required in `vendor/shared/contracts/**`
while its consumers are untouched. `@devdigest/shared` is the one contract
source — the change propagates by alias, so every package type-checks against
it in the same PR.

```sh
git diff "$BASE" -- server/src/vendor/shared/contracts | grep -E '^-\s+\w+:'
```

### `RULE-ALIAS-CI` — CRITICAL

CI path filters encode cross-package aliases: `reviewer-core/**` triggers
`server-unit` because the server type-checks against `../reviewer-core/src`. A
new or changed `paths` entry in any `tsconfig.json`, with no matching edit to
`.github/workflows/**`, creates a suite that never runs on the code that can
break it.

### `RULE-INSIGHTS-LAST` — WARNING

`!**/INSIGHTS.md` must be the **last** entry of every `paths:` list in
`.github/workflows/**` — a negation before a positive pattern is overridden by
it. See the root [`INSIGHTS.md`](../../../INSIGHTS.md).

### `RULE-IT-SUFFIX` — CRITICAL

`*.it.test.ts` is the only thing separating the DB-backed lane
(`vitest run .it.test`) from the hermetic one (`--exclude '**/*.it.test.ts'`).
A new server test that spins up testcontainers or touches the DB without that
suffix runs in the unit lane and breaks it; the inverse (an `.it.test.ts` with
no DB) only wastes a container — WARNING.

```sh
git diff --name-only "$BASE" -- 'server/**/*.test.ts' | grep -v '\.it\.test\.ts$' \
  | xargs -r grep -lE "helpers/pg|dockerAvailable|startPg|testcontainers"
```

Match on those markers, not on `db.` or `drizzle(` — unit tests mock the
repositories and mention both constantly. Every DB-backed test in
`server/test/` reaches Postgres through `./helpers/pg.js`.

### `RULE-CORE-PURITY` — CRITICAL

`reviewer-core` is consumed as TS source through an alias. A finding here is:
a new runtime dependency in its `package.json`, an import of `pg`, `drizzle`,
`fastify`, `node:fs`, or a network client, or a `main`/`exports`/emitting
`build` that turns it into a published package.

```sh
git diff "$BASE" -- reviewer-core/src | grep -E "^\+.*from '(pg|drizzle-orm|fastify|node:fs|node:child_process)"
```

### `RULE-CLONES` — CRITICAL

`server/clones/**` is runtime data (git-ignored) — never committed, never
collected by a test suite.

### `RULE-VENDOR` — WARNING

An in-place edit under `client/src/vendor/**` or under a `.claude/skills/<name>`
that `skills-lock.json` pins to an upstream source. The next sync overwrites
it. If the edit is intentional, it needs its `computedHash` in
`skills-lock.json` updated in the same change. Locally-authored skills
(`onion-architecture`, `frontend-code-organization`, `engineering-insights`,
`commit`, `pr-self-review`) are not pinned and are free to edit.

### `RULE-PROMPT` — WARNING

A change under `server/src/prompts/**` or `docs/agent-prompts/*.md` is checked
against the shipping checklist in
[`docs/agent-prompts/README.md`](../../../docs/agent-prompts/README.md):
severity rubric using exactly `CRITICAL/WARNING/SUGGESTION` with an
anti-inflation rule, verdict mapping including "no findings ⇒ approve", no JSON
shape or markdown layout described in prose, no "return at most N findings"
quota. The `docs/` file and the shipped prompt must move together.

### `RULE-SKIPWORKTREE` — WARNING

`server/package.json` is `skip-worktree`; a local variant diverges from the
committed file and `git checkout` won't restore it. Seeing it in a diff is
usually accidental — confirm the change is meant for everyone.

### `RULE-LESSON` — WARNING

`main` is deliberately the starter state. A run cost badge, severity filter,
intent layer, smart diff, MCP server, blast radius, project-context folder,
eval pipeline, multi-agent review, plugin export, or agent dashboard landing on
a branch that targets `main` is homework in the wrong place — see the lesson
table in [`README.md`](../../../README.md#what-you-build-in-the-course).
